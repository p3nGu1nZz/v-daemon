# Agents in v-daemon

This repository defines the autonomous agents, skills, and conventions used by the v-daemon Director and Copilot CLI integrations. It documents where skills and agents live, how they run, what autogenerated artifacts look like, and the safety controls operators and agents must respect.

Key conventions

- Skills: describe each skill in .github/skills/<skill>/SKILL.md and implement the runtime helper in scripts/skills/<skill>.sh. Skill scripts should write outputs to run/skills/<skill>/<timestamp>/ and the SKILL.md `name:` field should match the skill name.
- Renamed skill: run-app (formerly run-project). Keep SKILL.md, scripts/skills/run-app.sh and docs/specs/scripts/skills/run-app.md in sync when renaming skills.

Prompts & Director

- Canonical prompts are centralized in scripts/lib/prompts.sh and are the authoritative source for prompts used by Director autopilot and skills.
- Director autopilot entrypoint is scripts/lib/actions.sh; it constructs a repository snapshot, invokes the Copilot CLI to produce summaries and plans, and writes audit artifacts under audits/ and run/skills/<skill>/.
- Autopilot uses locking (audits/director-summary.lock) to avoid concurrent runs; check audits/ and run/ for per-run diagnostics.

Docs and specs automation

- The update-docs skill (scripts/docs.sh) scans the repo, ensures docs/specs/_template.md exists, and can generate per-file specs under docs/specs/.
- The docs `build` subcommand compiles a project design/user guide and copies the compiled markdown and PDF to docs/v-daemon-user-design-guide.md and docs/v-daemon-user-design-guide.pdf (PDF only when pandoc is available).

Setup, patching and safety

- Setup: scripts/setup.sh supports --check to verify environment and --clean to remove generated artifacts (audits, logs, run) while ensuring runtime directories exist.
- Patching: scripts/skills/patch-repo.sh stages, commits, and pushes changes by default; scripts/lib/patcher.sh can be used for sandbox operations. Agents and automation should examine run/skills/patch-repo/<ts>/report.json for results and handle push failures.
- Safety: consult config/settings.toml (e.g. director.allow_execute) before letting agents perform destructive or wide-ranging changes. Autogenerated files include front-matter `autogenerated: true` — avoid overwriting authored docs unless explicitly allowed.

Guidance for contributors

- Use sh scripts/lib/actions.sh run to execute Director autopilot runs for local testing and inspect audits/ and run/ for outputs.
- Keep README.md, docs/ROADMAP.md, TODO.md, and PLAN.md aligned with the agent behaviors and milestones.

Purpose: provide an actionable, up-to-date reference for contributors, automated validators, and agents interacting with this repository.
